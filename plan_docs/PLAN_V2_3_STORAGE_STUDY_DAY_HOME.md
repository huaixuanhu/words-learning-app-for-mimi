## Stage 2.3.5 连接故障归因与隐藏风险

### 已确认的直接原因

- 2026-09-13 `10:37:12Z`、`10:38:25Z` 两次有界只读探测使用原有 Keychain 身份，目标项目、`main` 分支与 Sydney endpoint（连接端点）的哈希均与 V2.2 留存证据一致。
- 首个 `BEGIN ... READ ONLY` 请求被 SQLSTATE `53000` 拒绝，错误内容在进程内归类为 `network-transfer-quota-exceeded`。没有开始数据数量查询，没有读取学习内容；确认原因后停止重复 SQL 探测。
- Neon 控制台 API 的当前账户类型为 `free_v3`；本期 `2026-09-01T00:00:00Z` 至 `2026-10-01T00:00:00Z` 的 `data_transfer_bytes = 6,330,077,483`，约 6.33 GB。Compute（计算资源）仅为 3,756 CU-seconds，当前故障指向传输额度。
- `main` 仍为 `ready`，逻辑大小为 44,376,064 bytes，连接端点为 `idle`，没有被删除或禁用。最后活动为 `2026-09-12T15:44:14Z`，最近暂停操作在 `15:52:15Z` 开始、次秒完成；操作记录没有说明超额触发时刻，不能把该暂停操作单独认定为配额触发证据。
- 当前因传输额度无法执行记录计数。数据库存在和逻辑大小不证明逐条数据完整；留存的 2026-09-03 备份基线为 282 个词、125 个复习状态、441 条复习事件、22 张表，仅作为恢复后比较的历史锚点。
- 因果链：Neon 传输额度超限阻断查询 → 原应用连接异常未被完整处理 → 原客户端将加载失败显示为空词库。前两轮只读日志和本轮直接连接证据相互补充；没有证据支持实际删库或词汇被清空。

### 已确认的流量放大路径

- 每张卡激活时的 `refreshPrompt` 和每次评分都会读取该学习者完整的数据快照，包括全部词汇、复习历史、每日计划、创建事实、导入记录及 AI 记录；正常单卡至少两次整份读取，队列进入和重试另外计入。
- 每次评分会通知其他打开的页面；每个页面再获取一份包含全部有效学习者的完整快照。浏览器增量更新没有减少这些数据库到服务器的传输。
- 普通 Home 解析会在计划稳定后停止变化；Insights 的分钟计时仅进行本地计算。没有发现 V2.2 普通单页持续自动查询的循环或定时数据库任务。
- 这些读取方式足以构成随历史增长而加重的明确风险，但当前没有逐请求传输统计，不能将 6.33 GB 全部精确归因给某一接口、页面或学习操作。
- 合成模型按历史基线数量构造 282 个词、441 条事件、1,486 条创建事实，整份 API JSON 约 1.06 MB；估计两次数据库文本行传输约 1.35 MB/卡，不含其余协议流量。留存备份的汇总字节元数据也显示 13 张相关表的 canonical JSON（规范化 JSON）合计约 1.21 MB。这些仅说明量级，不替代本月真实用量归因。

## Stage 2.3.7 保存结果与本机恢复保护

- 同时提交相同内容只执行一次，已一致的状态编辑跳过写入。
- 提交成功但后续快照失败，服务端返回明确的已提交状态；前端只补读数据，不重放写入。
- 提交响应丢失时仅进行一次读取核对，未能正向确认的操作阻止后续通用保存，并保留跨页面刷新的待核对标记。此标记限同一浏览器来源与运行环境；学习者选择仍允许，Study 使用既有独立持久化命令保护。没有新增持久化通用命令表，不把未确认结果宣称为严格的任意操作只执行一次。
